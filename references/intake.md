# 不同输入的起步方式

## 核心原则

接受自然语言、截图、文件和混合输入，不要求用户提供订单或改成指定格式。用户明确说已订可记录为 confirmed，无需截图证明；“想坐这班”“考虑住这里”仍是 tentative 或 candidate。对冲突信息只澄清影响安排的部分。

未知事实留空；为了产出初版采用的规划假设单独记录，并在交付时明确。先帮助用户认识目的地，再逐步收敛，不把信息收集变成准入门槛。

## 按已知信息起步

| 用户输入 | 立即可做 | 不可默认 |
| --- | --- | --- |
| 只有目的地 | 介绍片区、代表景点、交通、住宿区域；按目的地尺度给短游和慢游两档天数与 Day 1 等示例路线，并推荐一档 | 出发城市、实际日期、已订交通、酒店、预算 |
| 目的地和天数，没有日期 | 按相对天数安排片区与节奏，列出季节及开放日影响 | 星期、节庆举办、特定日期有票、天气预报 |
| 有日期，没有机票 | 按可用日期形成草案，将首尾日作为可调整的到离时间窗口 | 用户会一早到达、最后一天可玩整天、实际航班已定 |
| 只有单程机票 | 锁定该航段；仅有去程则从抵达后安排，给推荐停留天数；仅有返程则倒推机场缓冲，前段仍开放 | 自动补一张返程票、固定总天数、原路往返 |
| 往返或多段机票已定 | 以每段当地时间、机场和可用游玩时间为边界，识别跨城和开口行程 | 到达机场与返程机场相同、跨夜日期或联程行李直挂 |
| 有酒店，不论有无机票 | 已确认入住区间内以实际酒店为路线锚点；未覆盖日期标待定 | 一晚订单代表全程同住、入住日期就是旅行起止 |
| 没有酒店 | 比较两三个适合片区的交通、氛围及换宿成本；先用明确标注的住宿区域参考点估算路线 | 将某间推荐酒店标成已订、用城市中心伪装酒店精确位置 |
| 混合信息或已有攻略 | 合并已知事实和新增变化，只调整受影响部分 | 覆盖旧确认安排、重复追问已知答案 |

未知日期时优先写 Day 1、Day 2 和弹性时段；周几营业、季节活动、价格或预约需要标明适用范围。开放规则可核验当前一般规则，但不能推断未知旅行日期一定开放。

## 提问与交付

首次可问一到三个对决策最有影响的问题，例如大概天数或月份、节奏与兴趣、实际出发城市（需要研究外部交通时）。提问同时提供初版；用户不回答就采用明确假设继续。普通观光初版不必先追问年龄、完整预算和所有餐饮偏好。

涉及安全、无障碍或无法兼容的固定预约时，说明具体缺口；不以假设解决关键风险。精确航班、实际到达时间等未知时，暂不生成看似确定的接机或赶飞机方案。

只有目的地的初版至少包含：目的地认识、建议停留时长及理由、两种节奏的示例安排、住宿片区选择、交通概览、假设与待确认事项。用户仅问某一方面时缩小交付范围；用户明确要求地图时可以直接做示例地图，显式标明方案待定。

后续日期、航班或酒店补齐后，将相对日期映射为实际日期，复核营业日、预约、首尾日可用时间、跨时区交通以及住宿出发路线，再同步更新所有成品。不得把示例安排悄悄升级成已确认事实。
